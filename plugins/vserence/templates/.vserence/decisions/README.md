# Архитектурные решения

Одна запись = один файл `NNNN-<короткое-имя>.md`, читается по требованию, в контекст не грузится.
Записываются решения, дорогие к отмене: хранилище данных, схема БД, публичный API, внешний провайдер,
формат файлов, границы модулей; а также любой отход от принятого в проекте паттерна.

Шаблон:

```markdown
# NNNN. <Решение>
Дата: YYYY-MM-DD · Статус: принято | заменено NNNN

## Контекст
Что не так с текущим положением или паттерном.

## Решение
Что выбрано и чем оно лучше; где граница его применения.

## Отброшенные варианты
Вариант — почему нет.

## Последствия
Что становится проще, что сложнее, как откатить.
```
