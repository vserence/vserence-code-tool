# Стандарт безопасности

Работает вместе с хуками плагина security-guidance. Уровень: ASVS L1 для всех сервисов, L2 для сервисов с деньгами и персональными данными (определяется по критичным модулям `project.md`).

## Принципы
1. Проверка прав на каждый запрос: аутентификация и авторизация на сервере для каждого действия и каждого объекта (владелец объекта = текущий пользователь или есть роль).
2. Всё входящее — запросы, файлы, вебхуки, фиды — проверяется по схеме на границе системы до использования.
3. Секреты вне кода и логов: только переменные окружения или хранилище секретов; в логах маскируются.
4. Зависимости без известных уязвимостей: новая или обновлённая зависимость проверена аудитом пакетного менеджера.
5. Запросы к БД и командной строке только с параметрами; вывод в HTML экранируется.
6. Вебхуки проверяют подпись и отбрасывают повторы (метка времени/nonce).
7. Ошибки наружу без стека и внутренних деталей.

## Как проверить
- [ ] Каждый новый обработчик содержит проверку прав; есть тест «чужой пользователь → 403/404» на объект другого владельца (IDOR).
- [ ] Каждая новая точка входа валидирует данные по схеме; тест на невалидный вход.
- [ ] Поиск в diff по `key`, `secret`, `token`, `password`: нет литералов; логирование не выводит эти поля.
- [ ] Аудит зависимостей (`npm audit`, `pip-audit`, `govulncheck`, `cargo audit` или аналог) без high/critical на добавленных пакетах; результат в отчёте.
- [ ] Нет конкатенации строк в SQL и shell-командах.
- [ ] Вебхук: проверка подписи + тест на неверную подпись.
- [ ] Для L2 (деньги, ПДн): журнал действий с объектом без ПДн в открытом виде; ограничение частоты на вход и чувствительные операции.

## Антипаттерны
- Проверка прав только во фронтенде или только на списке, но не на получении по id.
- Доверие полю `role`/`user_id` из тела запроса.
- Логирование целого запроса с заголовком Authorization.
- Принятие файла по расширению без проверки содержимого и размера.

## Плохо / хорошо
```text
ПЛОХО:
  GET /invoices/{id}: return db.invoices.get(id)
ХОРОШО:
  GET /invoices/{id}:
    user = auth.require(request)
    inv = invoices.get(id)
    if inv is null or inv.ownerId != user.id and not user.has("billing:read"): return 404
    return inv
```
