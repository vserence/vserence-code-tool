# Стандарт данных и БД

## Принципы
1. Операции, меняющие несколько связанных записей, выполняются в одной транзакции; уровень изоляции указан явно, если отличается от умолчания.
2. Миграция работает со старой и новой версией кода одновременно (расширить → перенести → сузить) и имеет откат.
3. Новый запрос проверен планом выполнения (EXPLAIN) на объёме данных, близком к продакшену.
4. Один владелец данных: таблицу меняет только модуль-владелец из `project.md`.
5. Правила инвалидации кэша записаны явно: какой ключ, при каком изменении, кто сбрасывает.
6. Ограничения целостности (NOT NULL, UNIQUE, FK, CHECK) в схеме, а не только в коде.

## Как проверить
- [ ] Каждое место, где в одном действии меняется > 1 запись, обёрнуто в транзакцию (видно в diff); нестандартная изоляция указана.
- [ ] Миграция не удаляет и не переименовывает колонку/таблицу, которую читает текущая версия кода; есть down-миграция; тест: up → down → up на тестовой БД.
- [ ] Для каждого нового/изменённого запроса в отчёте план EXPLAIN на данных ≥ объёма продакшена из `project.md` (или «не проверено» с причиной); нет Seq Scan по большим таблицам без причины.
- [ ] Запись в чужую таблицу отсутствует (поиск по имени таблицы вне модуля-владельца).
- [ ] Для нового кэша в коде или `decisions/` записано правило инвалидации и есть тест «изменение → кэш сброшен».
- [ ] Уникальность, на которую опирается логика, обеспечена UNIQUE-индексом.

## Антипаттерны
- Переименование колонки одной миграцией при работающем старом коде.
- Чтение → проверка → запись без транзакции/блокировки (гонка).
- N+1 запрос в цикле.
- Кэш без TTL и без явного сброса.
- Миграция данных без батчей на большой таблице.

## Плохо / хорошо
```text
ПЛОХО: одна миграция
  ALTER TABLE users RENAME COLUMN name TO full_name   -- старый код упадёт во время выкладки
ХОРОШО: расширить → перенести → сузить (три выкладки)
  1) ADD COLUMN full_name; код пишет в обе колонки, читает name
  2) backfill батчами; код читает full_name
  3) DROP COLUMN name (отдельная задача, после удаления чтений); у каждого шага есть down
```
```text
ПЛОХО: balance = select(...); if balance >= x: update(balance - x)
ХОРОШО: transaction(isolation=serializable): update accounts set balance = balance - x where id=? and balance >= x; check rows == 1
```
