# Миграции данных

## 1. Несовместимость со старым кодом во время выкладки
- **Симптом:** ошибки 500 в окне выкладки.
- **Причина:** миграция удалила/переименовала колонку, которую читает ещё работающая старая версия.
- **Как предотвратить:** расширить → перенести → сузить; удаление — отдельной выкладкой после удаления чтений.
- **Как проверить тестом:** тесты старой версии кода проходят на схеме после миграции.

## 2. Нет отката
- **Симптом:** неудачную выкладку нельзя откатить без потери данных.
- **Причина:** нет down-миграции или она теряет данные.
- **Как предотвратить:** каждая миграция с down; необратимые — только с вопросом человеку (условие 5) и бэкапом.
- **Как проверить тестом:** up → down → up на тестовой БД с данными, данные совпадают.

## 3. Блокировка большой таблицы
- **Симптом:** сервис недоступен минуты во время миграции.
- **Причина:** ALTER/UPDATE по всей таблице в одной транзакции, создание индекса с блокировкой.
- **Как предотвратить:** батчи, неблокирующее создание индексов (где СУБД умеет), миграция данных отдельно от схемы.
- **Как проверить тестом:** миграция данных на объёме, близком к продакшену, — время и отсутствие долгих блокировок в отчёте.

## 4. Частично применённая миграция данных
- **Симптом:** половина записей в новом формате, половина в старом.
- **Причина:** сбой посреди переноса, перенос не идемпотентен.
- **Как предотвратить:** перенос идемпотентен и возобновляем (маркер обработанного), код читает оба формата до завершения.
- **Как проверить тестом:** прервать перенос на середине и запустить снова → все записи в новом формате ровно один раз.

## 5. NOT NULL без значения по умолчанию
- **Симптом:** миграция падает в продакшене, хотя прошла на пустой тестовой БД.
- **Причина:** добавление обязательной колонки в таблицу с данными.
- **Как предотвратить:** добавить nullable → заполнить → сделать NOT NULL.
- **Как проверить тестом:** миграция на тестовой БД с существующими строками.
