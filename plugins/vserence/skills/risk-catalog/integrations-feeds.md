# Внешние интеграции и фиды

## 1. Зависание на внешнем вызове
- **Симптом:** запросы висят, пул соединений исчерпан.
- **Причина:** нет таймаута у внешнего вызова.
- **Как предотвратить:** таймаут на подключение и ответ у каждого вызова; ограничение параллельности к одному провайдеру.
- **Как проверить тестом:** фейковый сервер не отвечает → ошибка через заданный таймаут, не дольше.

## 2. Изменился формат фида или ответа
- **Симптом:** импорт падает или молча пишет пустые/неверные данные.
- **Причина:** нет проверки по схеме на границе, поля читаются «как есть».
- **Как предотвратить:** валидация по схеме; невалидная запись в отчёт об ошибках, а не в БД; порог доли ошибок, при превышении импорт останавливается.
- **Как проверить тестом:** фид с отсутствующим полем и неверным типом → запись отклонена с причиной, остальные импортированы.

## 3. Частичный импорт и дубли при повторе
- **Симптом:** после сбоя и повтора записи задвоены или пропали.
- **Причина:** импорт не идемпотентен по внешнему id.
- **Как предотвратить:** upsert по внешнему id; уникальный индекс; обработка удаления записей из фида явным правилом.
- **Как проверить тестом:** один фид импортирован дважды → число записей не изменилось.

## 4. Лимиты провайдера
- **Симптом:** ошибки 429, блокировка ключа.
- **Причина:** нет учёта rate limit, ретраи без задержки.
- **Как предотвратить:** клиент учитывает лимиты и Retry-After; повтор с растущей задержкой и лимитом попыток.
- **Как проверить тестом:** фейковый сервер отвечает 429 с Retry-After → повтор не раньше указанного времени, не больше N попыток.

## 5. Часовые пояса и форматы дат
- **Симптом:** события сдвинуты на часы, даты «плывут» (например, сетка бронирований).
- **Причина:** даты без пояса трактуются в поясе сервера.
- **Как предотвратить:** пояс фида записан явно, хранение в UTC, преобразование на границе.
- **Как проверить тестом:** запись фида с датой без пояса и с поясом → одинаковый момент в UTC по правилу; переход на летнее время.
