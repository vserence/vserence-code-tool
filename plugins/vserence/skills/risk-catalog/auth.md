# Авторизация и права

## 1. Доступ к чужому объекту по id (IDOR)
- **Симптом:** пользователь видит/меняет данные другого, подставив id.
- **Причина:** проверяется только вход, но не принадлежность объекта.
- **Как предотвратить:** проверка владельца/роли на каждом получении и изменении объекта, в одной общей точке (политика доступа).
- **Как проверить тестом:** пользователь B запрашивает объект пользователя A → 404/403 для get, update, delete.

## 2. Права не отзываются сразу
- **Симптом:** уволенный/понижённый пользователь сохраняет доступ.
- **Причина:** роли зашиты в долгоживущий токен или кэш без инвалидации.
- **Как предотвратить:** короткий срок жизни токена доступа; проверка актуальной роли для чувствительных действий; сброс сессий при смене роли.
- **Как проверить тестом:** снять роль → следующий чувствительный запрос с тем же токеном отклонён (в пределах заданного срока).

## 3. Повышение прав через поля запроса
- **Симптом:** пользователь назначил себе роль администратора.
- **Причина:** сервер принимает `role`, `is_admin`, `owner_id` из тела запроса (mass assignment).
- **Как предотвратить:** явный список разрешённых полей для каждого действия.
- **Как проверить тестом:** обновление профиля с `role=admin` → роль не изменилась.

## 4. Перебор паролей и кодов
- **Симптом:** аккаунты взламываются подбором.
- **Причина:** нет ограничения частоты попыток входа и проверки кодов.
- **Как предотвратить:** лимит попыток на аккаунт и IP с растущей задержкой; одноразовые коды с коротким сроком.
- **Как проверить тестом:** N+1 неверная попытка → блокировка/задержка; код после истечения срока отклоняется.

## 5. Сессия после выхода и смены пароля
- **Симптом:** старый токен работает после выхода или смены пароля.
- **Причина:** токены не инвалидируются на сервере.
- **Как предотвратить:** серверный список отозванных сессий или версия сессии в пользователе.
- **Как проверить тестом:** выход/смена пароля → запрос со старым токеном отклонён.
