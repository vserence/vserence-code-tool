# Очереди и фоновые задачи

## 1. Повторная доставка сообщения
- **Симптом:** письмо отправлено дважды, операция выполнена дважды.
- **Причина:** очередь гарантирует «хотя бы один раз», обработчик не идемпотентен.
- **Как предотвратить:** идемпотентный обработчик (ключ задачи + запись о выполнении с уникальным индексом).
- **Как проверить тестом:** одно сообщение доставлено дважды → эффект один.

## 2. Ядовитое сообщение
- **Симптом:** очередь стоит, одна задача падает бесконечно.
- **Причина:** нет лимита попыток и очереди недоставленных (DLQ).
- **Как предотвратить:** лимит попыток с растущей задержкой, затем DLQ и алерт.
- **Как проверить тестом:** обработчик всегда падает → после N попыток сообщение в DLQ, следующие обрабатываются.

## 3. Потеря задачи при остановке воркера
- **Симптом:** задача пропала после выкладки или падения.
- **Причина:** подтверждение (ack) до выполнения.
- **Как предотвратить:** ack после успешного выполнения; graceful shutdown по SIGTERM.
- **Как проверить тестом:** убить воркер посреди задачи → задача снова в очереди и выполнена.

## 4. Задача поставлена, а транзакция откатилась
- **Симптом:** задача обрабатывает несуществующую запись (или наоборот: запись есть, задачи нет).
- **Причина:** постановка в очередь и запись в БД не атомарны.
- **Как предотвратить:** outbox-таблица в той же транзакции или постановка после коммита с повтором.
- **Как проверить тестом:** откат транзакции → задачи нет; сбой после коммита → задача поставлена повторной отправкой из outbox.

## 5. Наложение запусков cron
- **Симптом:** два экземпляра периодической задачи работают одновременно.
- **Причина:** следующий запуск начался до окончания предыдущего или задача запущена на каждом инстансе.
- **Как предотвратить:** распределённая блокировка с TTL или единственный планировщик.
- **Как проверить тестом:** два параллельных запуска → один выполняется, второй пропускает.
