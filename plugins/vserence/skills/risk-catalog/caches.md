# Кэши

## 1. Устаревшие данные после изменения
- **Симптом:** пользователь видит старое значение после сохранения.
- **Причина:** нет правила инвалидации или оно не вызывается во всех путях записи.
- **Как предотвратить:** инвалидация в общей точке записи (у владельца данных); правило записано явно.
- **Как проверить тестом:** изменить данные → следующее чтение возвращает новое значение.

## 2. Лавина промахов (cache stampede)
- **Симптом:** при истечении ключа БД получает сотни одинаковых запросов.
- **Причина:** все запросы одновременно пересчитывают значение.
- **Как предотвратить:** блокировка на пересчёт одного ключа, случайный разброс TTL, ранний фоновый пересчёт.
- **Как проверить тестом:** 100 параллельных чтений истёкшего ключа → 1 обращение к источнику.

## 3. Утечка данных между пользователями
- **Симптом:** пользователь видит чужие данные.
- **Причина:** ключ кэша не включает пользователя/тенант/права; публичный HTTP-кэш персонального ответа.
- **Как предотвратить:** ключ включает все параметры, влияющие на ответ; `Cache-Control: private` для персональных ответов.
- **Как проверить тестом:** пользователь A прогревает кэш → пользователь B получает свои данные.

## 4. Кэш без ограничения размера
- **Симптом:** рост памяти процесса до падения.
- **Причина:** кэш в памяти без лимита и вытеснения.
- **Как предотвратить:** лимит элементов/байтов, вытеснение LRU, TTL.
- **Как проверить тестом:** вставка лимит + 1 элементов → размер не превышает лимит.
