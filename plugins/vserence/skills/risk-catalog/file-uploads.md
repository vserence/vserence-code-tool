# Загрузка файлов и медиа

Первая версия по истории taplink2 (9–20 ноября 2026, ~30 коммитов). 11 рисков.

## 1. Служебные дорожки в видео
- **Симптом:** транскодирование падает или результат без звука/с чужой дорожкой на видео с телефонов и камер.
- **Причина:** контейнер содержит кроме видео и аудио служебные дорожки (данные, метаданные, таймкод, субтитры), а команда обработки берёт все дорожки или первую попавшуюся.
- **Как предотвратить:** явно выбирать дорожки: первая видео + первая аудио (если есть), остальные отбрасывать; отсутствие аудио — допустимый случай.
- **Как проверить тестом:** фикстура-видео с дополнительной data/timecode-дорожкой → обработка успешна, в результате ровно 1 видео- и ≤ 1 аудиодорожки; фикстура без аудио → успешна.

## 2. Переменная частота кадров
- **Симптом:** рассинхрон звука и видео, неверная длительность, «дёрганое» видео после обработки.
- **Причина:** исходник с переменной частотой кадров (VFR, типично для смартфонов) обрабатывается как постоянная.
- **Как предотвратить:** определять VFR при приёме и приводить к постоянной частоте при транскодировании; длительность брать из контейнера, а не считать по кадрам.
- **Как проверить тестом:** VFR-фикстура → длительность результата совпадает с исходником в пределах 0.1 с, расхождение звука и видео ≤ 1 кадра.

## 3. Битые кадры
- **Симптом:** обработка падает на середине или зависает; превью — серый/зелёный кадр.
- **Причина:** повреждённые кадры или обрезанный файл (недогруженный), декодер останавливается с ошибкой.
- **Как предотвратить:** проверка файла декодером при приёме (probe + декодирование с допуском ошибок); превью брать не из первого кадра, а из первого корректно декодированного; ошибку декодирования переводить в понятный статус «файл повреждён».
- **Как проверить тестом:** обрезанная фикстура и фикстура с повреждёнными кадрами → статус «повреждён» или успешный результат, без зависания (тест с таймаутом).

## 4. Повреждённые PDF
- **Симптом:** падение воркера или пустой предпросмотр на некоторых PDF.
- **Причина:** битая структура (xref), шифрование, нестандартные шрифты; парсер бросает исключение, которое не обработано.
- **Как предотвратить:** проверка PDF при приёме (открывается, число страниц > 0, не зашифрован или явно поддерживается); ограничение времени и памяти на рендер; ошибка → статус «файл повреждён».
- **Как проверить тестом:** фикстуры: битый xref, зашифрованный, 0 страниц → понятный статус, воркер жив, следующий файл обрабатывается.

## 5. Лимит размера фото
- **Симптом:** загрузка фото с современной камеры отклоняется или процесс падает по памяти.
- **Причина:** лимит размера файла или разрешения ниже реальных фото; декодирование полного изображения в память (мегапиксели × 4 байта).
- **Как предотвратить:** лимиты по байтам и по пикселям заданы явно и проверяются до декодирования (по заголовку); уменьшение потоково/через уменьшающий декодер; лимит сообщается пользователю заранее.
- **Как проверить тестом:** фото на границе лимита принимается, лимит + 1 байт/пиксель отклоняется с понятной ошибкой; фото 50+ Мп обрабатывается без превышения лимита памяти воркера.

## 6. Осиротевшие загрузки
- **Симптом:** хранилище растёт, файлы без записей в БД (или записи без файлов).
- **Причина:** файл сохранён, а запись не создана (сбой, отмена, закрытая вкладка), или запись удалена без удаления файла.
- **Как предотвратить:** статус загрузки (pending → ready) и уборщик, удаляющий pending старше N часов и файлы без записей; удаление записи ставит задачу удаления файла.
- **Как проверить тестом:** загрузка, прерванная после сохранения файла → через срок уборщика файла нет; удаление записи → файл удалён.

## 7. Повтор после сохранения
- **Симптом:** дубли файлов и записей после повторной отправки или ретрая клиента.
- **Причина:** клиент повторяет запрос после таймаута, хотя сервер уже сохранил файл; нет идемпотентности.
- **Как предотвратить:** ключ идемпотентности/хеш содержимого на загрузку; повтор возвращает уже созданный объект.
- **Как проверить тестом:** два одинаковых запроса загрузки с одним ключом → одна запись, один файл, одинаковый ответ.

## 8. Зависание после сбоя и неудачной отмены
- **Симптом:** загрузка навсегда в статусе «обрабатывается», кнопка отмены не помогает.
- **Причина:** воркер упал посреди обработки, статус не откатился; отмена не учитывает уже запущенную задачу.
- **Как предотвратить:** у статуса «обрабатывается» есть срок (heartbeat/lease), по истечении — повтор или «ошибка»; отмена переводит в «отменено» и задача проверяет флаг отмены между шагами; конечные статусы определены для всех переходов.
- **Как проверить тестом:** убить воркер посреди задачи → через срок lease статус «ошибка» или повтор; отмена во время обработки → статус «отменено», результат не публикуется.

## 9. Общий лимит места
- **Симптом:** заканчивается диск/квота хранилища, падают все загрузки.
- **Причина:** нет квоты на пользователя/проект и общего контроля; временные файлы обработки не удаляются.
- **Как предотвратить:** квоты по пользователю и общий лимит проверяются до приёма; временные файлы в отдельной папке и удаляются в finally; метрика и алерт заполненности.
- **Как проверить тестом:** пользователь на квоте → загрузка отклонена с понятной ошибкой; после ошибки обработки временные файлы удалены.

## 10. Остановка обработки при обслуживании и выкладке
- **Симптом:** после выкладки часть файлов зависла или обработана наполовину.
- **Причина:** воркер убит во время выкладки без завершения текущей задачи; задача не возвращается в очередь.
- **Как предотвратить:** по SIGTERM воркер перестаёт брать задачи и доделывает текущую в пределах grace-периода; незавершённая задача возвращается в очередь (ack после завершения); обработка идемпотентна.
- **Как проверить тестом:** SIGTERM во время задачи → задача завершена или возвращена в очередь и затем обработана ровно один раз.

## 11. Скорость сжатия видео
- **Симптом:** обработка длится дольше таймаутов, очередь копится, пользователи ждут.
- **Причина:** пресет кодировщика слишком медленный, нет ограничения длительности/разрешения, обработка в одном потоке на большой файл.
- **Как предотвратить:** пресет выбран по замеру (время на минуту видео), лимит длительности и разрешения на входе; обработка в очереди с таймаутом больше худшего замеренного случая; прогресс виден пользователю.
- **Как проверить тестом:** замер на эталонной фикстуре (1 мин 1080p) укладывается в заданный бюджет времени; файл длиннее лимита отклоняется до обработки.
